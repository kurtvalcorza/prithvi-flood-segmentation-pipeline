## Two things this tutorial does that most of the fleet's others do not

**It converts a pickled checkpoint in the runtime and says so.** The upstream file is a Lightning checkpoint; Section 3 prints the static audit (the four globals the pickle would import, 0 violations, the pinned audit digest) and the conversion record (the checkpoint's epoch and step, the converted file's digest) before the model loads, and the provenance export records `served_from_pickle: false`.

**It adapts a model that already trained on the tutorial's data, and does not pretend otherwise.** The 44 chips come from the official Sen1Floods11 splits the checkpoint was fine-tuned on; the bounded adaptation is selected by validation loss with the frozen model as epoch 0, the paired held-out comparison is printed without a directional assertion, and the notebook states that the contract exists for the learner's own chips from another sensor, season or region.

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules (`pipeline.py`, `samples.py`, `metrics.py`) verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 7-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes all seven entries and asserts the checkpoint's digest against the package constant; `PrithviFloodPipeline.from_pretrained(weights_dir=..., report=print)` audits and converts the pickle when the safetensors file is absent, verifies it against the pinned digest, builds the model from `terratorch` and loads it strictly. The pickle is unpickled exactly once, in that conversion, through torch's weights-only loader, after the audit.
- **Stages (§4.1):** `fetch_sample_dataset` / `load_byod_dataset` (sample acquisition) → `dataset_manifest` + `validate_dataset` refusal probes (validation, with the ceilings and a dataset digest) → roles from the official splits (train / validation / test) → `pipe.evaluate` on the frozen model with the no-water baseline (baseline) → `pipe.adapt` (bounded decoder fine-tuning) → `pipe.evaluate` on validation and test with the three-way comparison (evaluation) → `pipe.predict` on the upstream example chips (inference) → `pipe.save_artifact` → `PrithviFloodPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the softmax scores are the model's outputs, labelled uncalibrated; the decision rule is the argmax with no threshold, and the notebook says the threshold and its cost trade-off are the deployment's to set.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the no-water baseline is scored on the same pixels as every model number, and every metric is labelled as pixel-pooled tutorial sample-sanity evidence from 12 test chips with no dispersion estimate.
- **Split integrity (SPL1–SPL8):** roles come from the official Sen1Floods11 splits, never from shuffling chips; validation metrics select the epoch and the test chips are used for nothing but the final evaluation; the notebook states that neighbouring chips are near-duplicates and that real data must be split by scene or event; the preprocessing statistics are the upstream constants, fitted on nothing here. In BYOD mode the seeded split is by chip and the notebook says to group by scene.
- **Ceilings (VAL6):** the chip size, the band count and order, the reflectance range and scaling, the label vocabulary and the record range are stated in the Prerequisites and printed from the schema before the model runs; three refusals are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user chips flow through the same validation, baseline, adaptation, evaluation, inference, export and reload cells. The expected zip layout, the band contract and the privacy guidance — licensed imagery and unreleased assessments are restricted data — are stated in the Prerequisites and in Section 4, and a sample pair is written to `outputs/` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
